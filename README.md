# Neural-operator surrogates for outdoor acoustics (LEE–FDTD)

This repository accompanies the paper “Towards Neural-operator Surrogates for Outdoor Acoustics using Parameterized Wind Profiles and Terrain” (JASA submission, currently under review).

We learn operators that map parameterized wind profiles $U(z)$ and/or terrain profiles $h(x)$ to complex acoustic pressure fields on a fixed 2D region-of-interest (ROI) grid:

- $G_U: U \mapsto p(x,z)$
- $G_h: h \mapsto p(x,z)$
- $G_{U,h}: (U,h) \mapsto p(x,z)$

All models predict two output channels $[p_{\mathrm{re}},\, p_{\mathrm{im}}]$ on the ROI grid, SPL is derived by postprocessing.

## Scripts

### FNO (grid-to-grid)
- `train_fno_wind_coords.py`  
  Wind-only FNO. Consumes wind-on-grid (optionally $dU/dz$) + normalized coordinates.

- `train_fno_terrain_eta_mask_coords.py`  
  Terrain-only FNO. Consumes $\eta_{\mathrm{norm}}$, air mask $m$, and normalized coordinates. Loss/metrics can be masked to the air region.

- `train_fno_joint_wind_terrain_eta_mask.py`  
  Joint wind+terrain FNO. Inputs include wind-on-grid, $\eta_{\mathrm{norm}}$, air mask, and coordinates (optionally $dU/dz$ and a visibility channel).

### DeepONet with grid trunk (FNO-style trunk)
- `train_deeponet_wind_gridtrunk.py`  
  Wind-only DeepONet. Branch encodes $U(z)$ via sensors, trunk is a grid-based spectral (FNO-like) network over $(x,z)$.

- `train_deeponet_terrain_gridtrunk_eta_mask.py.py`  
  Terrain-only DeepONet. Branch encodes $h(x)$ via sensors, trunk uses grid coordinates with optional $\eta$ and mask features, outputs/metrics are masked to the air region.

## Running

### 1st Option -  Run on the included sample data
From the repository root (after you clone this repository), the defaults already point at `data_sample/...`, so you can just run for example:

```bash
python train_fno_wind_coords.py
...
```

### 2nd Option - Run on your own dataset folder
Each script has a `DATA_ROOT = ...` near the top. Point it to one of:

- wind-only dataset root (must contain `cases/` and typically `flat_ground.h5` 
- terrain-only dataset root (must contain `cases/` and typically `flat_ground.h5`)
- joint dataset root (must contain `cases/`, baseline is only needed if you enable residual-to-baseline training)


```bash
python train_fno_joint_wind_terrain_eta_mask.py --data-root <DATA_DIR> --iid --device cuda
```

Outputs are written to:
- `checkpoints/` (best + last model checkpoints)
- `evals/` (evaluation metrics as JSON, for scripts that run evaluation)

## Outputs and generated files (IID runs)

When you run any training script (`python train_*.py`), the code creates a few folders automatically.

### Dataset-side outputs (inside `DATA_ROOT/`)
- **`splits/iid/`**  
  Contains `train.txt`, `val.txt`, `test.txt` listing which HDF5 cases belong to each split.  
  **IID** (*independent and identically distributed*) means train/val/test are random splits from the *same overall distribution* (the same wind/terrain families can appear across splits). This measures “more of the same” generalization, not family hold-out.

- **`fno_aux/`** *(FNO scripts)* / **`deeponet_aux/`** *(DeepONet scripts)*  
  Caches helper files such as normalization statistics (and for DeepONet: sensor locations). This keeps preprocessing consistent across training and evaluation.

### Run-side outputs (created in your current working directory)
- **`checkpoints/`**  
  Saved model weights:
  - `<RUN_TAG>.pt` = best checkpoint (lowest validation loss)
  - `<RUN_TAG>_last.pt` = last checkpoint (useful for resuming)

- **`evals/`** *(scripts that run evaluation)*  
  JSON summaries of evaluation metrics, e.g. `evals/<RUN_TAG>__iid.json`.

## Data and representation

### ROI grid and complex pressure
Training data are generated by a 2D LEE finite-difference time-domain (FDTD) solver and stored as a complex phasor on the ROI grid using two channels:
- `p_re = Re(P)`
- `p_im = Im(P)`

### Terrain features on a fixed grid
Terrain is represented on the fixed ROI grid using a height-above-ground coordinate:

$$
\eta(x,z)=z-h(x)
$$

and supervision/evaluation can be restricted to the air region using the mask:

$$
m(x,z)=\mathbf{1}[\eta(x,z)\ge 0].
$$

When used as a feature, $\eta$ is scaled to $\eta_{\mathrm{norm}}$. Spatial coordinates are normalized to $[-1,1]$.

### Wind features on a fixed grid
Wind is provided as a vertical profile $U(z)$ and broadcast onto the ROI grid as $U_{\mathrm{grid}}(x,z)=U(z)$, then scaled to $U_{\mathrm{norm}}$ by a constant factor.

### Direct vs residual targets
Some scripts support either:
- Direct: $y(x,z)=p(x,z)$
- Residual: $y(x,z)=\Delta p(x,z)=p(x,z)-p_0(x,z)$, with reconstruction $p=\Delta p + p_0$

The fixed baseline $p_0$ is typically the “no wind + flat ground” case, stored as `flat_ground.h5` (included in the `wind/` and `terrain/` sample folders).
